FerriSync

Decentralised folder sync for your phone and your PC — direct, device-to-device over your own network. Devices find each other with mDNS and pair once with trust-on-first-use over TLS 1.3. No cloud, no accounts, no middleman.

Built for privacy

🏠

Your files stay home

Files travel directly between your devices over TCP + TLS 1.3. Nothing is stored on — or even routed through — a server you don't control.

🤝

Pair once, trust forever

TOFU pairing: devices exchange self-signed certificates and verify each other's blake3 fingerprint via QR code or IP. After that they trust each other indefinitely.

📡

Zero-config discovery

mDNS (_ferrisync._tcp) broadcasts each device's ID, name and address. No central registry, no setup — new peers simply appear on the network.

⚡

Fast, incremental transfers

blake3 content hashing, 64 KB chunks, and an index exchange that only sends what changed since the last sync — not the whole folder.

🖥

Two UIs, one engine

A native Flutter app for mobile & desktop, plus an interactive shell, a full-screen TUI and one-shot CLI commands — all driving the same Rust sync engine.

📚

Library-first

ferrisync-core is a reusable crate: embed sync in your own app instead of shelling out to a monolith. The GUIs are just clients of the library.

How it works

1

Devices find each other

mDNS on your local network advertises every FerriSync device's ID, name and address. Start it on both ends and they see each other — no accounts, no server.

2

Pair once

Scan the QR code (or enter the IP). Devices swap TLS certificates, check blake3 fingerprints, and store each other as trusted — trust-on-first-use, then never again.

3

Share a folder

Pick a folder, pick a device. Peers exchange indexes, diff by mtime + blake3 hash, and transfer whole files in chunks with per-file acknowledgement.

4

It stays in sync

A filesystem watcher pushes changes as you make them (500 ms debounce). Simultaneous edits resolve last-writer-wins; the losing copy is kept as .bak and logged to the activity history — nothing is silently destroyed.

Get started in two minutes

A Rust workspace — clone, build, run. Any two devices on the same network will do; no hardware or account needed.

# Build (Rust 1.80+)
git clone https://github.com/DavidNeurieder/FerriSync.git
cd FerriSync && cargo build --release

# Interactive shell (default)
cargo run -p ferrisync-tui
ferrisync> discover
ferrisync> pair 192.168.1.42
ferrisync> exit

# Full-screen terminal UI
cargo run -p ferrisync-tui -- tui

# …or one-shot commands
cargo run -p ferrisync-tui -- status
cargo run -p ferrisync-tui -- sync ~/Documents --device 192.168.1.42:9847
cargo run -p ferrisync-tui -- watch ~/Photos --device 192.168.1.42:9847

# Mobile & desktop GUI (Flutter + flutter_rust_bridge)
cd ferrisync-flutter
flutter pub get
flutter_rust_bridge_codegen generate
flutter run

One engine, thin clients

┌────────────────────┬───────────────────────┐
│ Flutter GUI        │ TUI + CLI (ratatui)   │
│ (mobile + desktop) │                       │
├────────────────────┴───────────────────────┤
│ ferrisync-core — sync engine               │
│ discovery · protocol · storage · crypto    │
├────────────────────────────────────────────┤
│ TcpTransport — TCP + TLS 1.3 (LAN)         │
│ QuicTransport — internet (planned, v3)     │
└────────────────────────────────────────────┘

Your files never leave your network. Sync runs device-to-device over your LAN — FerriSync has no servers, no relays and no telemetry. Internet sync via QUIC is a planned v3 milestone: opt-in, and built behind the same transport traits.
